# Scoring and verdicts

- **Document Unpaired Mutant Count, Unrun Share, Gate Exemption, and Null Failed Count.** When reviewing documentation about sources with no paired test, verify it states that their mutants are excluded from the score and are never placed in `no_verdict`, so they cannot fail `--threshold`. State that `AggregateResult#unrun_count` excludes unpaired mutants (the count stays the row total only) and that the reporter adds unpaired mutants to the unrun-share warning, omitting them from that warning under `--fail-fast`. In JSON report documentation, also state that a failed count for an unpaired source (for example in `unpaired_sources[].mutants`) is represented as `null`; only successful counts are numeric. (cubic `e9e96f0d`)
- **Score Uncovered Mutants by Backend.** When reviewing Mutineer scoring behavior or documentation, describe uncovered mutants as excluded in coverage-guided runs and as survivors under `--test-command` when no test reaches them. Not when: Do not apply the uncovered-mutant survivor rule to coverage-guided runs; the developer limits the exclusions to those runs. (cubic `cddaaf12`)
- **Document no-coverage probe semantics and edge-line retries.** When documenting Mutineer's `no_coverage` result, state that it covers both lines no test runs and mutations that a statement's tests do not reach, so readers do not misdiagnose existing coverage as an absence of tests. Define the probe criterion consistently across the `no_coverage` summary row, the `no_coverage[]` section, and the `attempted` row: the probe counts when the mutated expression returns during a test; a raise inside the expression, or a load-time call, does not count as returning. For a later-line mutant in a multi-line statement whose edge line shares other code, further explain that Mutineer retries tests covering the first or last line, never the `def` line, and that those tests may not have run the mutant. Not when: Do not apply the return-during-test probe rule to ordinary line-coverage descriptions or to expressions not evaluated by this probe. (cubic `072dd4fe`)
- **Stored Method Blocks at Load.** When a shared-line mutation is inside a block stored by `define_method` or `define_singleton_method`, classify it as `ran_at_load` if that call's line ran at load. For a survivor in any other block or lambda literal whose call ran at load, let the reach probe decide (#493): classify it as `ran_at_load` only when the probe is in the mutant's code and did not see the mutated expression return during a test. Not when: Do not move a survivor that the probe saw run, such as an `each` block that a test ran; it stays scored. Do not apply the probe rule to a `:maybe` selection, to a mutant with no conclusive probe in its code (none, one around `next`, `break`, `return`, `redo`, `retry` or a call of `raise`, `fail`, `throw`, `exit`, `exit!` or `abort`, or no probe in a `defined?` operand), to a block in a one-line or endless `def`, to a block whose call is the body of a modifier (`validate { } if c`) or of `&.` (no candidate), or to a `def` that reload places from a concern's hook block. A block call in a branch form whose line Ruby counts when it checks the condition (`if c then call { } end`) can still be a candidate; that limit is #507. Code: `JobPlan.stored_block_candidate?`, `JobPlan.stored_block_verdict`, `StatementLines.enclosing_block_lines` and `ReachProbe.conclusive?`. (cubic `48862659`, #493)
- **Unknown Reporter Counts.** When a direct `Reporter#report` caller omits method counts (`subjects:` or `unmutated_subjects:`), treat them as unknown: emit `null` for the JSON count fields and omit the human `No mutants:` row. Treat the two method-count values (`subjects` and `unmutated_subjects`) as one unit: when either argument is missing, both become unknown at the top of `report`, so a count never appears next to a `null` in either the JSON or human report. Retain zero when counts are explicitly supplied as empty. (cubic `8fa63e9b`)
- **Report Failed Unpaired Counts.** When `CLI.warn_empty_run` handles an empty run with nil unpaired counts, report that the count is unavailable rather than using a generic empty-run message. (cubic `0f5fc568`)
- **Summary Lines at Line Start.** In `--test-command` runs, `ExternalBackend.summary_mode` reads the clean run: when one of its summary lines starts a line, a mutant run's summary and `# Running:` lines count only at the start of a line (after colour codes, the start of the text or after `\n` or `\r`). Otherwise they count at any position, as in 1.9.0. After a SimpleCov gate, a failing or passing summary that is only away from a line start scores `error` with the reason "not at the start of a line". On exit 1, a failing summary that is only away from a line start scores `error` with that reason too, unless a line-start `# Running:` has no line-start summary after it: that reads as a run stopped during a test and scores `killed`. (#515, limits in #549)
- **Detect Interrupted Final Test Suite.** In `exited_during_tests?`, compare the last Minitest running marker with the last recognized Minitest or RSpec summary; treat the final suite as unfinished when the marker follows the summary. (cubic `83d3e6d4`)
- **Modifier Body Coverage Fallback.** When assigning fallback coverage in `Mutineer::StatementLines`, give modifier-body code on uncounted continuation lines no statement tests for `if`, `unless`, `while`, or `until` modifiers; keep a multi-line modifier condition attributed to the statement. (cubic `aa1e39a7`)
- **Clarify Mutation Score Scope.** When documenting Mutineer's mutation score, state that 100% means every scored change was caught and preserve the empty-score `null` behavior. (cubic `7c375e2d`)
- **Preserve Load-Time Survivor Status.** When a load-time survivor enters the `selection_verdict(:maybe, ...)` path after `load_verdict`, verify that its final status remains `:ran_at_load`. (cubic `95e39bb3`)
- **SimpleCov Gate Survivor Condition.** Document a SimpleCov gate-only mutant as `survived` only when SimpleCov prints its gate message, the run prints a passing summary line, and it prints at least as many summary lines as the clean run (`ExternalBackend.summary_count`, passed to `run` as `clean_summaries`). With fewer, the gate stopped a chain of suites and the mutant scores `error`. A clean count of 0 keeps the rule without the count. (cubic `dd1ca273`, #516)
- **Rails Connection Error Scoring.** When reviewing Mutineer RSpec database-error scoring, preserve the Rails-version distinction: `ConnectionNotDefined` is a code error scored `killed` on Rails 8, while the undefined-connection case on Rails 7.2 raises `ConnectionNotEstablished` and scores `errored`; other statement errors score `killed`. (cubic `a3415c1e`)
