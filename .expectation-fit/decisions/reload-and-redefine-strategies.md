# Reload and redefine strategies

- **Model ActiveSupport Prepended Hooks.** When reviewing `prepended` handling in the concern stub, preserve ActiveSupport's behavior: store the first block, raise `MultiplePrependBlocks` for a second block, and run the hook only on the first prepend. (cubic `e5066b28`)
- **Reload Concern Placement Boundary.** When documenting Mutineer `--strategy reload` for a mutated method from an ActiveSupport concern's `included` or `prepended` block, describe the placement as limited to a *placeable* method, state that hosts include or prepend the concern, and preserve the `unplaceable` result (`no_coverage` for a `:maybe` selection) for methods reload cannot place. Do not imply reload runs every hook-block mutant in a concern file containing an `included` or `prepended` block; such mutants that reload cannot place are `unplaceable` when their tests were selected as `:run`, and stay `no_coverage` when selected as `:maybe`. Not when: Do not say `--strategy reload` runs these mutants for a concern file with an `included` or `prepended` block under ActiveSupport. (cubic `b6084bd3`, updated 2026-11-16)
- **Safe Fallback for Mutated Blocks.** When reload replacement blocks have different compiled bodies, pair leftovers by place without code only when the old and new counts are equal; keep all copies when a same-place concern makes the counts differ. (cubic `76d6306d`)
- **Compare Callback Conditions.** In `ReloadGuards::RepeatedCallbacks.same?`, include ActiveSupport callback `if:` and `unless:` conditions when matching entries so callbacks with the same filter but different conditions remain distinct. (cubic `f365f80c`)
- **Normalize Optional Callback Kind.** When reviewing `skip_callback` argument handling, treat the kind as optional: if the first argument is not `:before`, `:after`, or `:around`, use `:before` and treat that argument as a filter, matching Rails normalization. (cubic `c893c69a`)
- **Dynamic Dispatch in Hook Self-Use.** In `placeable_hook`, treat `send`, `public_send`, and `__send__` like `method` and `instance_method`: count literal symbol or string names as self-use, and mark the whole hook block unplaceable when a name is computed at runtime. (cubic `4bb04fa6`)
- **Redefine Enclosing-Method Limits.** When documenting the `redefine` strategy for nested methods, state that it reloads directly enclosing methods and advise `--strategy reload` for methods nested in blocks such as `define_method`. (cubic `913fb352`)
- **Use Byte Offsets for ReachProbe.** When calculating source offsets passed to `ReachProbe.wrap` alongside byte lengths, use `byteindex` so the offsets and lengths share byte units. (cubic `71aa1755`)
- **Reset ReachProbe sentinel state.** When clearing a ReachProbe sentinel after load, also reset its process-local guard so a load-time run does not suppress recording a later test-phase run. (cubic `0a350852`)
- **Document Thread.current[] as Fiber-Local.** When documenting state stored with Ruby's `Thread.current[]`, describe it as fiber-local and clarify that it is not one value for the whole thread. (cubic `e6de3a59`)
- **Conditional Bootsnap Cache Setting.** For apps that call `Bootsnap.setup` directly, recommend setting `compile_cache_iseq` to `ENV["DISABLE_BOOTSNAP_COMPILE_CACHE"].nil?` so the cache is disabled only when that variable is set. Not when: Do not apply this rule to apps that do not call `Bootsnap.setup` themselves; the conditional guidance is for direct callers. (cubic `fd02fb46`)
- **Keep the Live Superclass on Reload.** When the reload text reopens a class whose superclass is a call (`Data.define`, `Struct.new`, `Class.new`), wrap the superclass in `ReloadGuards.kept_superclass` so the class reopens as the same object; a method inside the superclass call's block is `unplaceable` under reload. For a plain local write (`class Q < (base = Struct.new(:a))`), wrap only the written value, so the local is still set (#512). Not when: the superclass is a constant or a bare variable read, also in parentheses, or sets a local in another way (#527); or the expression reads a local from outside it, uses an instance, class or global variable, reads a constant the file writes with a value that is not a data literal and that reload does not keep, or calls a method the file defines (`JobPlan.reads_rebuilt?`); such a superclass keeps its text (#533, #574). (#492)
- **Keep Only a Literal Class Builder.** Keep a constant's value only when it is `Struct.new`, `Data.define` or `Class.new` with literal arguments (`Project.kept_builder?`). Any other value keeps its text and is built again on each load: that errors visibly only when a class statement of the file inherits from it or reads it in its superclass (#527), and is silent otherwise (#575). Not when: never widen this to a builder method of the file or an argument that reads a constant (#575). (#503, #528)
- **Keep Every Literal Class Builder Constant.** The reload text keeps the class of each constant write that `Project.kept_constant_write?` accepts: a bare write, or a path write whose parent is absent, a constant path or `self`, with a `Project.kept_builder?` value. No class statement has to name it. Discovery and the reload text both ask `Project.kept_constant_write?` and `Project.reopened_write?`. Not when: the name is in `Project.unkept_constant_names`: the file writes it more than once, or names it anywhere in the file (`Project.reshaped_constant_names`) other than as the receiver of `new` or `[]`, a path parent, a path write target, a class builder argument, a superclass, or a `class`, `module` or `class << X` statement whose body passes `Project.rerunnable_body?` (fail closed: `X.freeze`, `Alias = X`, `alias_method` in a reopen, also of `X::Inner`); and a file with a `Project::INDIRECT_RESHAPE_CALLS` call with a receiver (also through `send`, or a `send` with a computed name), an `eval`, or a `class << expr` with an unsafe body keeps no constant. A kept class would run that change again, and an `alias_method` chain would then call itself, a silent false kill. A change in another file is not seen (#585). (#528, #503)
- **Run a Builder Block Again Only When It Is Safe.** A kept builder's block runs again on the live class (`ReloadGuards.reopened_constant`) only when `Project.rerunnable_block?` is true: the block has no parameter, and each statement is a def, a `Project::RERUN_SAFE_CALLS` call with no receiver, no block and def or literal arguments, a constant write whose value is a literal builder or reads nothing of the class, or a `class`, `module` or `class << self` statement with such a body. Any other block is kept and not run, and each def in it is `Subject#not_reloaded`. Not when: never add a statement that reads the earlier state of the class (`alias_method`, `remove_method`, `include`, `extend`, a method wrapper); #576 tracks the methods that stay `unplaceable`. (#528)
- **Callback Growth Warning Is Report-Only.** When reviewing the reload callback-growth warning, keep it to one header line that counts each class once, and one line for each class and file whose own count grew, and keep verdicts, the score and the exit code unchanged; the JSON report only lists the same rows in `summary.callback_growth` (#505). Not when: a class only inherited its parent's growth. (#479)
- **Keep a Defined Callback Chain on Reload.** During a mutant load, `ReloadGuards::CallbackRedefinition` drops a `define_callbacks` name whose chain the class itself defined before the load (the class owns `_run_<name>_callbacks`), so concern and subclass callbacks stay and the class body's repeats pair through `RepeatedCallbacks`. Not when: the name is new to the class, or the call is outside a load; `reset_callbacks` is #530. (#504)
- **Mark a Def That Calls define_callbacks.** The reload skip drops the call's options, so discovery marks a def that calls `define_callbacks` or `define_model_callbacks` (any receiver) anywhere in its body, including inside a nested def or block, and a def of the file that calls such a def by name or through `super`, `Subject#calls_define_callbacks`: `unplaceable` under reload only. Not when: the def only computes the names or options, the call goes through `send`, `public_send`, `__send__` or `method`, or the caller is in another file (#530). (#504)
- **Mark a Def That a Second Load Skips.** A def inside the value of a constant `||=` write, or inside the guarded statements of `unless defined?(X)` or `if !defined?(X)` that write or open `X` (`Project.guarded_definition?`, matched by the last name), is `Subject#not_reloaded`: `unplaceable` under reload, counted in `summary.unplaceable`. Not when: the guarded statements do not define the tested name, or the def is in the `else` branch; other guards are #573. (#529)
- **Drop a Repeated Conditional Skip by Identity.** During a mutant load, `ReloadGuards.fresh_conditional_skips` drops a `skip_callback` filter with `if:` or `unless:` only when the class has that callback, and the class and each descendant that has one still has the callback object of `RepeatedCallbacks.snapshot` from before the load (`ReloadGuards.skipped_before_load?`). A filter with no callback in the class goes to Rails, so a wrong name still raises. Not when: never decide by the conditions the callback carries, because a class that adds its own callback with the same condition would lose one; a target with a new entry lets Rails run the skip for all (#578); an unconditional skip and a skip with a block are unchanged. (#543)
- **Mark a Def That Makes a Skip the File Runs.** Discovery marks a def that calls `skip_callback` or a `skip_*_action` (`Project::CALLBACK_SKIPPERS`, any receiver), or that calls such a def of the file by name, `Subject#makes_load_time_skip` (`unplaceable` under reload): every such def of the file, and only when the file calls one of them outside every def (`Project.load_time_call?`). A def whose name a load-time skip call has in its arguments is marked too (`Project.load_time_skip_arguments`). Not when: no load of the file calls the def, as for a concern's `allow_unauthenticated_access`; `send` and a caller in another file are #578. (#543)
