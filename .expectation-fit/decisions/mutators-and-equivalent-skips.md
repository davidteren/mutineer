# Mutators and equivalent skips

- **Condition Operator Applicability.** For methods with an `if`, `unless`, ternary, or modifier condition, recommend `condition_true` and `condition_false` to force branches; do not recommend them for empty methods or `case` bodies. Not when: Do not recommend these operators for an empty method or a `case`; they also do not mutate a one-statement `rescue` body. (cubic `86058bb7`)
- **Decline Discarded Inert Rescue Values.** When `rescue_body` encounters a discarded rescue-body or rescue-modifier value containing only literals, `self`, and local or instance-variable reads, decline the mutation and count it in `summary.declined_by_operator`. (cubic `1fdd8270`, updated 2026-11-16)
- **Skip Nil Rescue Expressions.** In `rescue_body`, skip emitting mutants for rescue-clause bodies and modifier values that are `nil`, `(nil)`, or `()`, because replacing them with `nil` changes nothing. (cubic `49d573d4`)
- **Skip mutations inside defined?.** Decline the `collection_method` mutation of an `each` or `map` call inside a Ruby `defined?` operand, including lazy chains and calls within an interpolated command, regexp, or string, because the operand is not evaluated. (cubic `89ea8885`, `e8b81439`)
- **Interpolation, Command, and Regexp Value Observation.** In `collection_method`, keep `each` and `map` mutations when the call provides the value read by string or symbol interpolation, a backtick or `%x` command, or an interpolated regexp (`/.../` or `%r{...}`), even when the resulting value is discarded, because interpolations call `to_s`, commands invoke `` Kernel#` ``, and regexps are compiled, so the result is observed. Do not extend this to earlier, non-final statements inside the interpolation; those are discarded and their mutations declined. Also note that `defined?` does not read its operand, so no result is observed there. (cubic `b710a356`)
- **Propagate Result Use Through Begin and For Bodies.** When evaluating result-use for a call in `Prism::RescueNode`, propagate from the rescue's `subsequent` and `consequent` bodies to the enclosing `begin`, so discarded values are declined and returned values remain swappable. In `Prism::ForNode` bodies, treat a call whose result is otherwise unused in the body, including when the `for` is the method's final expression, as discarded: Ruby `for` returns the collection, not the body value, so `each` and `map` cannot be distinguished by callers. Keep the mutation declined unless the call's result is consumed elsewhere. (cubic `01d05225`)
- **Hash Key and Value Result Handling.** In `CollectionMethod`, keep `each`/`map` calls in `Prism::AssocNode` keys observable because hash insertion invokes `hash`/`eql?`, and let calls in association values follow whether the enclosing hash result is used. (cubic `607d07aa`)
- **Qualify each/map equivalence.** Limit the `collection_method` discarded-result equivalence claim (in code review and in documentation of discarded `each` or `map` calls) to Enumerable semantics, and disclose that custom methods named `each` or `map` may differ because the syntax-only check cannot identify the receiver's class. (cubic `7c42a74f`, `226d7350`)
- **Parenthesized Endless Range Indexes.** For the `range` operator, do not describe a parenthesized endless range used as a slice index, such as `list[(1..)]`, as a built-in skip; it is swapped because the range is not a direct argument, even though the swap may be equivalent on an Array or String. (cubic `02f79f18`)
- **Treat Backticks as Unknown Receivers.** When `sequence_receiver?` handles an xstring or interpolated xstring as a slice receiver, treat it as unknown and swap the endless-range mutation because backticks invoke overridable `` Kernel#` ``. (cubic `35041744`)
- **Explain freeze observability.** When reviewing the `call_to_receiver` skip rationale for `freeze`, preserve that the receiver is returned frozen and that `frozen?` can distinguish it from the unfrozen receiver without a later write. (cubic `b816fd2a`)
- **to_set Membership Semantics.** When reviewing the `to_set` skip rationale, flag claims that Array and Set membership are universally equivalent; preserve the distinction that Array uses `==` and Set uses `eql?`. Not when: Do not imply membership results always differ; the distinction matters when Array `==` and Set `eql?` produce different results, as with `1` and `1.0`. (cubic `a44ecfcc`)
- **Document `--since` Filtering.** When documenting cross-operator deduplication for edits on different start lines, state that deduplication keeps both copies and `--since` filters each copy by its own start line. (cubic `d1dae0ff`)
- **Operator-Scoped Marker Suppression Scope.** When reviewing Mutineer documentation for operator-scoped inline `# mutineer:disable-line <operator>` markers, verify it states that the marker suppresses every mutant for that operator on the source line (not just one), and that readers should review all affected mutants. When the same line also contains a mutant that is not equivalent, do not use the line marker; the marker would hide that non-equivalent mutant too. Instead, use an `ignore:` id entry for only the equivalent mutant, so the non-equivalent one remains visible. Only consider a line marker acceptable when every mutant on that line is genuinely equivalent. (cubic `90332573`)
- **Truthiness-Only select and reject.** In `collection_method`, decline the swap of an argument-free `select` or `reject` whose value is only tested (an `if`, `unless`, `while`, `until` or subjectless `when` condition, also nested in `&&`, `||` or parentheses that are themselves only tested), because both return an always-true Array, Hash or Enumerator. Keep the swap when it has arguments (`IO.select`), and disclose that a custom method of that name can return false or nil. (#501)
