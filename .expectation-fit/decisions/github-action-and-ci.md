# GitHub Action and CI guidance

- **Describe Fork CI Approval Conditionally.** When documenting GitHub CI approval after a pull request is opened, say GitHub can hold CI on a pull request from a fork rather than implying it applies only to a contributor's first pull request. (cubic `d67b838e`)
- **Action Version Source Under Bundler.** When documenting Mutineer mapping-version requirements or the Action's `version:` input behavior, distinguish the `use-bundler` settings: with `use-bundler: false`, an empty `version` installs the latest gem, so readers must pin `version` (or rely on the documented mapping-version requirement); with `use-bundler: true`, the `version` input is ignored and the bundle's `Gemfile.lock`/Gemfile sets the version. Verify that any guidance describing empty-`version` behavior states this distinction and matches `action.yml`. (cubic `c9478f78`)
- **Action Directory Version Support.** When documenting the GitHub Action `test` input, state that Mutineer 1.9.0 or later accepts a directory and Mutineer 1.8.2 or earlier rejects one. (cubic `f7e61c85`)
- **Explicit Ref Checkout Availability.** When reviewing the GitHub Action's explicit `since` ref, verify that the ref is available in the checkout; recommend fetching it explicitly or using `fetch-depth: 0`. (cubic `bf32bc59`)
- **Expand Home-Relative Cache Paths.** When checking whether an Action output parent matches `cache_dir`, compare the literal output parent using `File.absolute_path` and expand `cache_dir` using `File.expand_path` so home-relative cache paths match absolute output parents. (cubic `9595ace3`)
- **Literal Tilde Report Paths.** When resolving `report=` from `OUTPUT`, use `File.absolute_path` so a literal leading `~` remains a path under the working directory rather than expanding as a home-directory shortcut. (cubic `511b4e09`)
- **Document Exact Prism 2 Check Name.** When reviewing the Prism 2 CI gate entry in AGENTS.md, verify that it uses the exact check context emitted by the workflow: `test (ruby 3.4, prism 2)`. (cubic `0def8b96`)
- **Full Scan When Tests Change.** When a Mutineer PR changes tests, including alongside source changes, require a full scan on the PR commit and compare it with the full baseline. (cubic `f1cf2116`)
