# CLI contract and exit codes

- **Project Load Exit Codes.** When reviewing Mutineer project-load behavior, verify that missing boot or `require:` paths remain usage errors with exit 2, while runtime load failures (an `ArgumentError` or `SystemCallError` raised while a boot file, a source file, or a `.mutineer.yml` `require:` file loads) exit 1 as runtime errors. When documenting this contract, keep the CHANGELOG, README exit-code list, Action metadata, STABILITY document, and other contract copies stating these exit-code distinctions consistently. (cubic `8ec1f1de`)
- **Missing Project File Exit Code.** When reviewing `Runner.require_project_file`, verify that missing requested Ruby or native-extension boot and require paths are checked before load errors are wrapped, preserving exit 2 for missing files. (cubic `7d01f9b5`)
- **Nil Framework Uses Minitest Hint.** When reviewing `JobPlan.abort_if_unclean!`, expect the seed hint when `framework` is nil; omit it only when a non-Minitest framework is explicitly selected. (cubic `0071250b`)
- **Cache-dir CLI prefixes.** When reviewing `extra-args` preflight handling for `--cache-dir`, recognize every unique CLI-accepted prefix, but exclude `--ca` because it is ambiguous with `--capture-timeout`. Not when: Do not treat `--ca` as a `--cache-dir` prefix; it is ambiguous with `--capture-timeout`. (cubic `4c0b9e3c`)
- **Explicit ChildCause Line Separators.** When reviewing line parsing or chomp in `ChildCause.line` or `ChildCause.read`, verify that the newline separator is passed explicitly so behavior does not depend on Ruby's global `$/`. (cubic `b482323c`)
- **Describe Empty-Run Counts.** When reviewing documentation of `CLI.warn_empty_run`, flag wording that says an empty run names methods; describe it as reporting how many methods it found. (cubic `ddeda55e`)
- **Document Mutineer Triage Invocation.** When documenting `mutineer triage`, specify the survivor selector: `--id ID` (repeatable) or `--all`. State that triage prints ignore entries using survivor IDs from a JSON report and a required separately supplied `--reason TEXT`, and does not edit files. A JSON report and `--reason` alone are insufficient without the selector. (cubic `a70c1f76`)
- **Ignore Mapping Reason Optionality.** When reviewing `.mutineer.yml` `ignore:` entries, verify that documentation and guidance describe a mapping as an `id` with an optional `reason`. (cubic `08085194`)
- **Old-ID Warning Match Condition.** When reviewing STABILITY.md's 1.8.0 old-ID warning contract, state that an old `ignore:` entry or baseline warns only when it matches a mutant in the current run. (cubic `2a75515b`)
