# Daemon and worker databases

- **First-Daemon Fallback Modes.** When reviewing documentation for a first-daemon boot failure, state that the one-worker fallback applies with `--rails`; with `--boot` alone, the run keeps its worker count. (cubic `675e6bf9`)
- **Match MySQL Worker Database Defaults.** When creating a MySQL worker database, read the test database's default character set and collation and use those values for the new database. (cubic `c38123c4`)
- **Clarify Rails 7.0 Worker Limits and Shared-Database Rails 7.1 Requirement.** When documenting or reviewing Rails `--daemon` multi-database behavior, distinguish the one-worker fallback for unshared extra databases from parallel runs with shared extras listed in `shared_databases`, which score every mutant `error` under Rails 7.0; state that only the primary database is copied. When documenting the `shared_databases` config key (e.g. in docs/cli.md), verify the row states the key is file-only and requires Rails 7.1 or later (on Rails 7.0 every parallel mutant scores `error`), and that listing the primary database exits 2. When a README support-matrix row or its supporting guidance (including the `docs/rails-setup.md` 'More than one database' section) advertises multiple databases with the extra ones in `shared_databases` as supported with `--daemon`, require that the row and the supporting bullet state 'Rails 7.1 or later', because Rails 7.0 scores every parallel mutant as `error` under that configuration. Also state the error condition precisely: a mutant scores `error` when a shared database still holds a connection (including from transactional tests), which is why the guidance warns that transactional tests that connect a listed shared database can make every parallel mutant score `error`. (cubic `7bfa716d`, updated 2026-11-22)
- **Shared Database Post-Test Pool Check Semantics.** When reviewing `shared_databases` documentation or behavior, treat each listed database as an explicit assertion that tests never use it while recognizing that the post-test Active Record pool check counts a connection that remains connected at check time, even if no test opened it: a pool connected at boot or in `setup` (e.g., transactional-tests pools registered in the test environment) counts, as does a pool that ran SQL during tests and was then disconnected or removed. Verify the documentation states that such a pool makes the mutant score `error`. Do not expect this check to detect direct-driver access or a connection closed/removed before the check runs, and do not rely on it to detect databases reached without Active Record. Not when: Do not apply the pool-counts-always rule to a connection that is closed or removed before the check runs and never ran SQL; it does not score `error`. (cubic `04a2863a`)
- **Reject a Listed Primary on Lookup Failure.** When `worker_count_for` handles a failed database lookup, check any resolved primary name before falling back to one worker, and reject the run if `shared_databases` lists it. (cubic `43d2012e`)
- **Match Replica Pools to Writers.** When checking Rails replica pools against shared databases, associate each pool with its shared writer by class (`connection_name` on Rails 7.1 and 7.2, `connection_descriptor.name` on Rails 8), while retaining database matching as a second rule. (cubic `c7ba67fc`)
- **Database-Free Boot Worker Count.** When a booted app has no `ActiveRecord::Base` and the daemon database report is nil, preserve the requested worker count; do not force one worker for that database-free case. Not when: Do not preserve the requested worker count for a nil report when ActiveRecord::Base is defined and the database inventory lookup has failed. (cubic `3b2eae89`)
- **Strategy-Specific Read-Only Fallback.** When documenting Mutineer's read-only source-directory behavior, state that only `redefine` falls back to a system temporary file and that `reload` requires a writable source directory. (cubic `9b916889`)
- **Normalize Rails Schema Formats.** When `schema_format_for` handles a global or per-database Rails schema format, normalize string values to symbols before checking the format or passing it to Rails' schema-path lookup. (cubic `d7d0710a`)
- **Scope Rails daemon guidance.** When reviewing Rails setup guidance for `--daemon`, limit the recommendation to Minitest with a supported database; direct RSpec and serial-only setups to use `--rails` alone. (cubic `a727cc24`)
- **Document Rails Daemon Worker Limits and MySQL Versions.** When reviewing documentation for Rails `--daemon` MySQL behavior, verify it states that one database runs in parallel while more than one database runs one worker, and that versions older than 8.0 stop while MariaDB, MySQL 9 or later, and unreadable versions warn and continue. (cubic `f1b0bb9c`)
- **Test daemon schema-path selection.** When reviewing tests for daemon schema-path selection, verify they exercise `DaemonServer#setup_worker_db` and check the path it stores so a fixed `db/schema.rb` regression fails. (cubic `b4010342`)
- **SQLite Schema File Selection.** When reviewing SQLite worker schema selection, verify that documentation states a missing schema file leaves the copy unchanged and that `SCHEMA`, when set, selects the file. (cubic `576dc5c3`)
- **Schema Path API Support.** For this gem's Ruby 3.4+ supported runtime, call `ActiveRecord::Tasks::DatabaseTasks.schema_dump_path` without a Rails-version `respond_to?` fallback. Not when: Do not apply this rule if the gem changes its supported Ruby floor or otherwise supports a Rails version whose DatabaseTasks lacks schema_dump_path. (cubic `400434d8`)
