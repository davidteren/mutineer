# Pairing of sources and tests

- **Respect pairing precedence in test ownership and concern failure attribution.** Apply pairing precedence consistently: a test belongs to the source that claims it under the pairing ownership rule. In `Pairing.test_given_as_source?`, preserve a same-directory split-test exemption only when no longer source on disk claims that test under the pairing ownership rule. In `exact_failed_test?` for a Rails concern under `app/<dir>/concerns/`, accept a failed namespace-path test only when `Pairing.infer_tests` finds no test at the concern's `concerns/` path (both exact and split tests block it, for Minitest and RSpec); do not attribute the namespace-path failure to the concern when an own-path test exists. For split tests at the `concerns/` path, treat a split owned by a longer source as not a pairable test for the shorter concern, so it does not block the fallback to a namespace-path test; the `concerns/` path takes precedence only when it has a pairable test (exact or split owned by the short concern). In concern namespace pairing, `claimed_by_longer_concern?` must exclude a namespace split from a shorter concern's pairing only when the longer concern has no test at its own `concerns/` path; when the longer concern already has an own-path test, keep the split available to the shorter concern and do not add it to the longer concern's pairing. Not when: Do not apply the namespace-path failure-attribution restriction when no test exists at the concern's `concerns/` path; a failed namespace test still attributes to the concern in that case. Do not treat a longer-source-owned split at the `concerns/` path as a pairable test for the shorter concern. (cubic `0c593ceb`, `194c899a`)
- **Qualify Concern Fallback Path.** When documenting the concern namespace fallback, state that it applies to sources at `app/<dir>/concerns/<rest>.rb` only. (cubic `ec8c4ef6`)
- **Document Full Namespace Fallback Paths.** When documenting a concern's namespace-base fallback, include the full path built by `Pairing.candidates`, including its mirrored directory. (cubic `a9953744`)
- **Load-Only Line Pairing.** When reviewing standalone load-only-line coverage, treat only tests returned by `Pairing.infer_tests` through naming convention as paired; do not count a `tests:` map entry, and retain every test when none pair. (cubic `33715709`)
- **Outside-Root Test Path Segments.** When `Pairing.test_given_as_source?` checks an outside-root path, read `test/` and `spec/` segments from the relative path as typed; treat absolute outside-root paths as having no segments. (cubic `370353d4`)
- **Recognize Concern Blocks Safely.** When reviewing Mutineer's concern-block discovery, assign `ClassMethods` ownership only when the module ran `extend ActiveSupport::Concern` earlier in the same file; otherwise retain the block's name and mark it unplaceable rather than guessing an owner. (cubic `f293ce28`)
- **Other class_methods naming.** When documenting Mutineer subjects, state that `class_methods` methods outside the recognized concern class-body case retain their enclosing name and are unplaceable under `redefine`. (cubic `db08f2b0`)
- **Distinguish Anonymous Minitest Classes.** When tracking Minitest parallel queue places for anonymous classes that inherit the same test method, key each place by the class object and attach the place to its result so the classes remain distinct. (cubic `cfead5a0`)
