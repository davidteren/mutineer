Equivalent skips

Mutineer skips some code changes to reduce results that rarely help improve tests. These built-in skips cannot be turned off. Chain-call skips use the method name only, so they are not always equivalent. Endless-range skips are equivalent.

For an equivalent mutant that does appear, use # mutineer:disable-line or an ignore: entry and record a reason. An ignore mapping contains an id and an optional reason; it requires Mutineer 1.7 or later everywhere the configuration is read. Older versions do not apply mappings and do not warn, so the named mutant is not ignored. mutineer triage prints these entries using survivor ids from a JSON report. Select survivors with --id ID (repeat it for more than one), or use --all for every survivor. Supply the reason with the required --reason TEXT argument. The command does not edit files. See Suppressing equivalent mutants.

Chain link

The chain_link operator removes a call from the middle of a chain. The call_to_receiver operator removes the last call. Both skip the names below without checking the receiver or next call. Conversions and copies often leave the result unchanged. Removing a middle new sends the next call to the class. That can raise an error or reach a class method that builds the instance itself. Removing a final new leaves the class in place of an instance.

Endless range

The range operator swaps .. and .... An endless range (1.. or 1..nil) is skipped. (1..) and (1...) give the same result for slicing, include?, ===, size, and patterns, so the mutant is equivalent.
