- **#1**: Coverage capture discards each test's pass/fail (`coverage_map.rb:337`, fork path `:224`), and per mutant any failure counts as killed (`minitest_integration.rb:54` -> `isolation.rb:218`). One unrelated red test turns every mutant on its covered lines into a phantom kill, and a `--threshold` CI gate passes on an inflated score. `ExternalBackend.smoke_check!` (`external_backend.rb:161`) exists for exactly this reason, but only on the `--test-command` backend. Fix: record pass/fail during coverage capture; abort (like `SmokeCheckError`) or exclude red tests with a stderr warning.
- **#2**: `Project.discover` selects on `qualified_name == only` and no caller checks for zero matches; an empty aggregate exits 0 (`reporter.rb:110`). Every other bad name (operator, format, file, git ref) exits 2. Empty-run-passes is deliberate for `--since` (docs-only PRs), but `--only` names one specific subject. Fix: zero matches with `config.only` set warns "unknown subject NAME" and exits 2.
- **#3**: `report` calls `html_report` with no `threshold:`/`baseline:` arguments (`reporter.rb:39-47`), while the CLI gates the exit code on both for every format (`cli.rb:493-494`). The archived HTML (the artifact a human opens to learn why CI went red) shows a normal-looking score with no verdict, no threshold, no new-survivor list. Verified; graded P2 because the artifact omits but never misleads, and the documented CI-gate path (`--format json` + exit code) is complete. Fix: thread `threshold:` and `baseline:` into `html_report` and render a PASS/FAILED banner plus a baseline-delta section.
- **#4**: `format` defaults to `json` (`action.yml:65`), stdout lands raw in a collapsed `::group::` block, there is no `$GITHUB_STEP_SUMMARY` write, and the README quick-start never overrides `format`. A developer whose PR fails the gate sees one giant single-line JSON blob (`JSON.generate`, `reporter.rb:186`). Verified; graded P2 because the default is deliberate (agent-first, machine-readable) and the user fix is one line. Fix: always write a short human summary (score, PASS/FAIL, survivor count) to `$GITHUB_STEP_SUMMARY` regardless of `format`. See the annex, items 4 and 5.
- **#5**: `survivors_html` renders a flat card list; the file name only appears in each card's small meta line, while the human report groups under file headings (`reporter.rb:587-599`). Fix: group survivor cards under a per-file heading, matching the human renderer's `group_by`.
- **#6**: `CLI.execute` prints nothing between config resolution and the report; `WorkerPool#run` has no per-item hook. A run forking hundreds of suites (up to 300 s each under `--test-command`) is silent for minutes, indistinguishable from a hang. Fix: a periodic "N/M mutants complete" line on stderr, keeping stdout byte-exact for `--format json`/`--output`.

## Tensions

- **Timeout verdicts** (`result.rb:8`, confidence 50): mutant/PIT/Stryker count a timed-out mutant as detected (the hang IS the suite catching it); mutineer groups timeout into no-verdict, and enough of them fail the completeness gate. Fail-safe conservatism vs domain convention. If the choice stays, announce the divergence in the README score section.
- **Unknown operator leniency** (#14): a shared `.mutineer.yml` should not brick runs when a newer config names an operator this version lacks (DWIM), but the same typo should fail the same way regardless of where it was typed (least astonishment).
- **HTML per-source sort** (`reporter.rb:199`, confidence 50): alphabetical keeps the array byte-stable for diffing (documented for JSON); reusing it for HTML buries the worst-scoring file.
- **Dark mode** (`reporter.rb:210`, confidence 50): the light palette clears WCAG AA on its own terms; a `prefers-color-scheme` block is aesthetic alignment, not a usability failure.

## Observations

- The verdict taxonomy (`lib/mutineer/result.rb`) is exemplary: eight named states, an explicit prohibition on conflating error/skipped, nil-never-0.0 score discipline shared across all three formats.
- Dry-run is WYSIWYG done right: it reuses `Runner.collect_jobs` and `filter_since` (`cli.rb:511-550`), so the preview cannot drift from a real run's job selection.
- `FileSwap`'s `ConcurrentRunError` and `restore_orphans`' heal notice are model explicit-failure design.
- The convention lens ran `bundle exec rake yard:strict` directly: 100.00% documentation across 41 files / 267 methods, matching the AGENTS.md rule exactly. No `eval`, no `rbenv exec`, zero runtime deps in the gemspec: all verified holding.
- The 11 mutator classes follow one identical shape; the only naming wrinkle (`regex` operator, `RegexLiteral` class) is applied consistently everywhere and reads as deliberate brevity.
- Value-object style is a reasoned dual convention: `Data.define` for immutable objects, `Struct.new(keyword_init: true)` for objects mutated after construction.
- Deliberate non-knobs are documented in place (`Reporter::BROKEN_SHARE_LIMIT` "deliberately not a flag"); ponytail comments mark known ceilings.
- `--list-operators` labels tier-2 operators "disabled" while `--help` says "optional", and the label stays "disabled" even when the operator is enabled in `.mutineer.yml`.
- A failed coverage capture is persisted into `.mutineer/coverage.json` and re-warned on every cached run, but the warning never says how to force a rebuild (delete the cache file).
- An empty run with `--output` writes a zero-byte report file and still prints "Report written to ...".
- `action.yml`'s `report` output echoes the `output` input verbatim; with a non-`.` working-directory the path will not resolve from the workspace root without prefixing.
- **CI / conventions delta:** auto-discovered gates (curated mode): `ci.yml` (test, docs, rails-integration jobs). `release-pr.yml` and `release.yml` excluded by the default `*release*` glob. No `severity_align` promotions (the built-in test-gate theme is coverage-note-only). One drift: 14 `# rubocop:disable <Cop>` comments across 8 lib files while no `.rubocop.yml`, no rubocop dev dependency, and no rubocop CI step exist (suppressed finding, confidence 55): either wire RuboCop in with a minimal config that collapses the inline disables, or strip the dead comments.

## Verdict — top 3 posture gaps

1. **Make the gate's truth reach every surface** (#1, #2, #3, #4). The score model is rigorous internally, but a red suite can inflate the score silently, a typo'd `--only` greens CI, and the two surfaces humans actually open on failure (the HTML artifact, the Action log) do not show why the run failed. These four share one shape and one theme: the pass/fail story exists in the code but does not reach the reader.
2. **Close the CI-consumer loop on the GitHub Action** (#4, #6, plus annex items 1, 4, 5): default `since` from `GITHUB_BASE_REF`, write `$GITHUB_STEP_SUMMARY`, emit per-survivor `::error` annotations, and add a progress line. Small diffs, and together they deliver the visible half of a GitHub App with zero hosting.
3. **One mechanical cleanup PR** (#7, #8, #9, #10, #15, #16, #17, #18, #20): dead constant, setterless knob, never-shipped aliases, superseded method, duplicate requires, forwarding shim, three one-line `gated_auto` fixes. All P3, all safe, one small branch.

# Annex — GitHub Action / skip-config parity (requested alongside the audit)

The ask: "if used as a GitHub app, only validate the new tests, and a config to bypass or skip like RuboCop does." Both halves are mostly shipped; the gaps are specific.

## What already exists

**Diff-scoped runs ("only validate the new code"):**

- `--since REF` mutates only lines changed since a git ref (`lib/mutineer/cli.rb:98`); the ref must resolve or the run exits 2 (`cli.rb:357-373`).
- Semantics are **line-level**, not file-level: `ChangedLines.parse` reads `git diff --unified=0` hunks (`changed_lines.rb:31-42`) and `Runner.filter_since` keeps only mutants on changed lines (`runner.rb:304-313`).
- The Action exposes `since:` (`action.yml:22-27`); the README PR recipe wires `since: origin/${{ github.base_ref }}` with `fetch-depth: 0`. `since` is also a `.mutineer.yml` key (`config.rb:37`).

**Skip/bypass ("like RuboCop"):**

- **Inline, line-level, operator-scoped:** `# mutineer:disable-line [ops]` (`runner.rb:275-284`), the analogue of same-line `# rubocop:disable`. Block-form ranges are intentionally unsupported (`runner.rb:274`).
- **Config-file, id-based:** `.mutineer.yml` `ignore:` list of stable content-based ids (SHA256[0,12] of subject + operator + token + occurrence, `mutant_id.rb:31-36`). Suppressed mutants are `:ignored`, never forked, excluded from the denominator, so 100% stays reachable. Each survivor's `id` is copy-pasteable from the JSON report.
- **Grandfathering:** `--baseline FILE` diffs by stable id and gates only new survivors / score drops (`baseline.rb:63-82`), the moral equivalent of `.rubocop_todo.yml`.

## Gaps vs the RuboCop model

| RuboCop capability | Mutineer status | Evidence |
|---|---|---|
| Same-line disable comment | **Exists** (operator-scoped) | `runner.rb:275-284` |
| Block disable/enable, disable-next-line | **Missing** (block form by design) | `runner.rb:271-274` |
| Path excludes (`AllCops Exclude` globs) | **Missing entirely**: no `exclude` key, no glob filter anywhere | `config.rb:37` KNOWN_KEYS |
| Per-cop (operator) excludes per path | **Missing**: `operators` is one global list | `cli.rb:100`, `config.rb:37` |
| `--auto-gen-config` / todo file | **Partial**: `--baseline` grandfathers, but there is no generator; ids are copied by hand | `README.md:211-212` |
| `inherit_from` / config merging | **Missing**: first `.mutineer.yml` found wins | `config.rb:64-77` |

## GitHub Action vs GitHub App

Today the composite action surfaces failure as **exit code only**: no `::error` annotations, no PR comment, no `$GITHUB_STEP_SUMMARY` (repo-wide, `::error` appears only in `release.yml:33`). `since` defaults to empty, so diff-scoping is opt-in and the caller must set `fetch-depth: 0`. A genuine GitHub App would add Checks-API annotations under its own identity, but workflow-command annotations (`::error file=F,line=L::msg`) deliver inline PR-diff annotations **from the action itself**, with no App, no token, no hosting.

## Smallest-diff proposal (ranked)

1. **Default `since` from `GITHUB_BASE_REF`** in `action.yml` (~3 lines of bash). Makes "only validate the new code" the out-of-box PR behavior; the line-level filter already does all the work. Size S.
2. **`exclude:` glob list in `.mutineer.yml`**: add the key to `KNOWN_KEYS`, coerce with the existing array pattern, filter after `Pairing.expand_sources` with stdlib `File.fnmatch?`. This is the `AllCops Exclude` gap. Size S/M.
3. **`--update-ignore` writer**: append current survivors' ids to `ignore:` with a `# Subject#method (operator)` comment each; reuses ids the reporter already emits. This is the `--auto-gen-config` equivalent. Size M. (Fix audit finding #11 first so the ids being written are edit-stable.)
4. **`$GITHUB_STEP_SUMMARY` in `action.yml`**: render score + PASS/FAIL + top survivors via `jq` (~20 lines). Also resolves audit finding #4. Size S.
5. **Per-survivor `::error` annotations in `action.yml`**: a `jq -r` loop over `survivors[]`. The visible half of a GitHub App, for free. Size S.
6. **`disable-next-line` marker**: extend `suppress_map` to map `line + 1`. Optional. Size S.

**Do not build:** a GitHub App (items 4-5 cover the CI surface with zero infrastructure); block disable/enable ranges (deliberately rejected; line markers + stable ids cover real cases); `inherit_from` (single-file walk-up is enough until a monorepo user asks); per-path operator config (RuboCop-scale machinery without demonstrated need).
